## 2026-09-14 (게시글 조회 — 옛 글 오기 전에)

### 바뀐 것 (마이그레이션 031)
- 게시글 색인을 조회 모양에 맞췄다. 옛 색인은 `(board, is_pinned, created_at, id)`
  로 시작했는데 실제 조회는 언제나 `deleted_at = ''` 로 거르고 `id` 로 줄을 세운다.
  - `idx_posts_list (deleted_at, board, id)` — 목록·건수·이전글/다음글
  - `idx_posts_pinned (deleted_at, board, is_pinned, id)` — 고정 공지
  - 방향은 적지 않는다. 두 엔진 모두 색인을 거꾸로 훑을 수 있다.
  - 실행 계획으로 네 조회 모두 새 색인을 타는 것을 확인했다(건수는 COVERING).
- 공통 조회식(NUMBERED)이 게시판을 밖에서 걸러, 번호와 첨부 수를 **모든 게시판의
  글에 대해** 먼저 구하고 버렸다. 공지 한 장을 여는 데 산업뉴스까지 훑는 셈이다.
  게시판을 조회식 안으로 넣었다. 번호는 게시판별로 매기므로 값은 같다.
  (옮기기 전후 글 번호가 같은지 대조해 확인)
- 메인 새소식이 게시판마다 한 번씩 줄 세워 묻던 것을 동시에.
- PostgreSQL 에 제목·본문 검색 색인(pg_trgm GIN). `LIKE '%말%'` 은 앞에
  와일드카드가 붙어 보통 색인을 못 쓰는데, 세 글자씩 쪼개 색인하면 쓸 수 있다.
  - 확장을 켤 권한이 없는 곳도 있어, 실패해도 마이그레이션이 멈추지 않게 했다.
    색인이 없어도 검색은 지금처럼 동작한다. 느릴 뿐이다.
  - **두 글자 검색은 여전히 훑는다.** 세 글자부터 색인이 걸린다.
  - SQLite 는 그대로 뒀다. 개발용이라 글이 얼마 없다.

### 아직 남은 것
- 목록은 글 번호를 매기느라 그 게시판 글을 모두 한 번 훑는다(`ROW_NUMBER`).
  게시판 밖까지 훑던 것은 없앴으므로 공지·행사는 문제없지만, 산업뉴스에
  11,000건이 들어오면 목록 한 장마다 11,000줄을 세게 된다.
  그때는 번호를 창 함수 대신 `id 이하 개수` 로 세어 보이는 줄에만 구하면 된다.
