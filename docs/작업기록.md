## 2026-09-24 (여섯 번째 점검 — 서버 시각)

### 고친 것 — '새벽 4시'가 실제로는 한국 시각 오후 1시였다 (`b3379a9`)
우분투가 처음에 UTC 라 cron 의 `0 4 * * *` 가 **한국 시각 13:00** 이었다.
**백업과 보관기간 파기가 업무 시간 한복판에 돌고 있었다.** 로그 시각도 아홉 시간
어긋나 보여, 사고를 쫓을 때마다 더하기를 해야 했다.

    timedatectl set-timezone Asia/Seoul

바꾸기 전에 자료에 영향이 없는지 먼저 확인했다.
- DB 에 넣는 시각은 앱이 `toISOString()` 으로 만들어 늘 UTC 다(`driver.ts` 의 `now()`)
- 한국 날짜가 필요한 곳은 따로 아홉 시간을 더한다(`format.ts` 의 `kstDate`)
- 시각 칸이 모두 TEXT 이고 DB 가 스스로 시각을 넣는 곳(`DEFAULT now()`)이 없다
- 관리자 대시보드의 날짜는 이미 `timeZone: "Asia/Seoul"` 로 막아 두었다

바꾼 뒤 서버에서 다시 확인 — 서버는 20:08 KST 인데 `now()` 는 `11:08` (UTC),
`kstDate()` 는 한국 날짜. **자료에 영향 없음.** 설치 문서 1-2a 로 단계를 넣었다.

### 고친 것 — 막혔을 때 맨 영문 화면이 나가던 것 (`058a968`)
    429 Too Many Requests
    nginx/1.24.0 (Ubuntu)

영어인 데다 까닭도 안 알려 주고 **서버 종류와 판 번호까지 함께 나갔다.** 사무실처럼
여러 분이 한 회선을 쓰는 곳에서 사업공고가 뜬 직후 몰리면 마주칠 수 있는 화면이다.
점검 안내와 같은 결로 `deploy/toomany.html` 을 만들어 붙이고('점검 중'이 아니라
'잠시만 기다려 주세요' — 까닭이 다르다), `server_tokens off` 로 판 번호를 감췄다.
확인: 429 에 한글 안내가 나가고 `Server: nginx` 로 바뀌었다.

### 고친 것 — 배포가 남기는 것의 주인 (`fdefb34`)
배포를 root 로 돌리므로 git 도 root 로 돌았다. `.git/objects` 246개 중 **200개가
root 것**이 되어, 앱 계정으로 한 번 받으려 하자 막혔다
(`insufficient permission for adding an object`). 실제로 겪었다.

git 을 앱 계정으로 돌린다(받기·되돌리기 양쪽). `rollback.sh` 도 같은 문제가 있어
함께 고쳤다 — `git reset` 을 앱 계정으로, 바꿔치기한 `.next` 를 앱 계정으로.
아니면 **되돌린 뒤부터** 그림 캐시가 다시 막힌다.

> **배포 도중에 `git pull` 로 스크립트가 바뀌면 그 회차는 옛 판으로 돈다.**
> 오늘만 세 번 걸렸다. 스크립트 자체를 고쳤을 때는 한 번 더 돌려야 반영된다.

### 고친 것 — 쓰지도 않는 번호를 매기고 있었다 (`4c2ec22`)

### 고친 것
- **`npm ci` 가 어긋나면 멀쩡히 돌던 사이트가 오히려 내려가던 것.** `npm ci` 는
  `node_modules` 를 지우고 새로 깐다. 인터넷이 잠깐 끊겨 중간에 실패하면
  `node_modules` 가 반쯤 깔린 채 남는데, 되돌리기가 **아무 때나 서비스를 다시 켰다.**
  그 지점까지는 돌고 있는 판을 건드리지도 않았으므로 가만두면 사이트는 멀쩡한데,
  다시 켜는 순간 반쯤 깔린 `node_modules` 로 뜨려다 못 뜬다. 그래 놓고 화면에는
  "사이트는 배포 전 상태입니다" 라고 적었다.
  이제 **빌드를 바꿔치기한 뒤에 어긋났을 때만** 다시 켠다
- **되돌릴 때 `node_modules` 짝을 다시 맞춘다.** `npm ci` 가 돈 뒤에 어긋났으면 지금
  `node_modules` 는 되돌린 코드와 짝이 맞지 않는다. 돌고 있는 프로세스는 이미 읽어 둔
  것으로 버티지만 다음에 켤 때 못 뜬다. 되돌리면서 `npm ci` 를 한 번 더 돌린다
- **바꿔치기 전에 어긋났는데 `.next` 를 옛 빌드로 덮던 것.** 그 시점의 `.next` 는
  아직 돌고 있는 판 그대로라 손대면 안 되는데, 직전 배포가 남긴 `.next.prev`
  (한 판 더 오래된 빌드)로 덮어썼다. 돌고 있는 사이트의 CSS·JS 주소가 어긋난다.
  이제 바꿔치기한 뒤에만 되살린다
- 카페24에서 우분투는 24.04 만 고를 수 있어, 서버 결정 줄도 24.04 로 맞췄다
  (배포 문서는 `9d6fec7` 에서 이미 고쳤다)

- **올린 파일** — 저장 이름은 서버가 정한 UUID 라 원본 이름이 경로에 닿지 않고,
  읽을 때 `safeStoredName` 이 UUID 모양만 통과시킨다. 실행 가능한 확장자는 막고,
  그림이라고 올린 것은 **앞머리 바이트를 견줘** 정말 그림인지 본다(브라우저가 적어 보낸
  형식은 믿지 않는다). SVG 는 그림으로는 통과하지 못하고, 첨부로 올라가도
  `Content-Disposition: attachment` + `nosniff` 라 브라우저가 열지 않고 내려받는다
- **지운 파일이 디스크에서도 사라진다** — 휴지통 30일이 지나면 야간 정리가

- **백업 스크립트** — 자리가 모자라면 시작하지 않고, 덤프를 뜬 뒤 `pg_restore -l` 로

## 2026-09-23 (PostgreSQL 로 처음 올리기 전 점검)

여태 돌려 본 것은 모두 SQLite 다. 운영은 PostgreSQL 이므로 **두 DB 가 갈리는 지점**을
먼저 훑고, 이어서 서버 액션·본문 HTML·토큰을 보았다.

### 고친 것
- **놀던 커넥션이 끊기면 서버가 통째로 죽던 것.** `pg` 는 놀고 있는 커넥션이 끊기면
  Pool 에 `'error'` 를 쏜다. 받는 곳이 없으면 Node 규칙대로 '잡히지 않은 예외'가 되어
  프로세스가 그대로 내려간다. DB 를 다시 띄우거나(apt 업그레이드·백업) 네트워크가
  잠깐 끊기면 놀던 커넥션이 한꺼번에 끊기므로, **조회 한 번 실패로 끝날 일이 사이트
  전체가 내려가는 일**이 된다. systemd 가 5초 뒤 다시 띄우지만 DB 가 늦게 돌아오면
  5분에 5번을 넘겨 죽으면서 systemd 가 손을 놓는다(StartLimitBurst). 그러면 사람이
  `reset-failed` 를 해 줄 때까지 사이트가 내려가 있다. 받는 곳을 두었다.
  여기서는 PostgreSQL 을 띄울 수 없어 `pool.emit('error')` 로 직접 확인했다
- 되돌리기(ROLLBACK)도 실패하면 그 오류가 위로 올라가 **진짜 원인이 로그에서
  사라지던 것.** 원인 쪽을 남기고 되돌리기 실패는 따로 적는다
- **로그인이 걸리는 시간으로 가입 여부가 드러나던 것.** 안내 문구는 "이메일 또는
  비밀번호가 올바르지 않습니다" 로 같지만, 가입된 주소일 때만 scrypt 가 돌아 응답이
  늦어진다. 재어 보니 **31.5ms 대 0ms** 였다. 없는 계정일 때도 헛걸음을 시켜 맞췄다
  (`burnPasswordTime`). 고친 뒤 45.5ms 대 45.2ms. 비밀번호 재설정에서 메일을 나중에
  보내는 것과 같은 까닭이다
  - 다만 **가입 폼은 "이미 가입 신청된 이메일입니다" 라고 대놓고 알려 준다.** 승인제
    가입에서 달리 안내할 방법이 마땅치 않아 그대로 둔다. 그러니 이번 고침은 새 자물쇠가
    아니라 저장소가 스스로 세운 원칙에 맞춘 것이다
- 검사 `tests/password.test.ts` 를 새로 썼다. 맞는/틀린 비밀번호, 소금이 매번 다른지,
  **한글 비밀번호가 자판·기기에 따라 달리 담겨도 통하는지**(NFKC), 망가진 저장값,
  없는 계정 헛걸음

### 확인했고 문제 없던 것
- **두 DB 가 갈리는 자리** — `is_locked`·`is_pinned` 가 PostgreSQL 쪽도 SMALLINT 라
  `= 0` 이 양쪽에서 통한다(BOOLEAN 이었으면 운영에서만 깨진다). SQL 문자열 안에 `?` 가
  없어 `$n` 치환이 안전하다. **`COUNT(*)` 를 담는 30여 곳이 모두 `Number()` 로 감싸여
  있다** — PostgreSQL 은 BIGINT 를 문자열로 주므로 한 곳만 빠져도 더하기가 글자 잇기가 된다
- **서버 액션 74개 중 63개에 문지기가 있고, 없는 11개는 모두 공개여야 하는 것**
  (로그인·로그아웃·가입·소셜가입·재설정 3개·뉴스레터 신청·신청 조회·조회수·방문기록).
  이 중 행을 만드는 공개 통로에는 방문기록만 빼고 모두 횟수 제한이 걸려 있다
- **본문 HTML 정화** — 공격 문자열 20가지(script·onerror·javascript:·svg onload·
  iframe·form·meta refresh·base·style·link·object·대소문자 섞기·중첩 태그·외부 이미지·
  주소 우회 등)를 넣어 보았다. **20개 모두 막혔다.** 날것으로 그리는 두 곳(`Prose html=`)도
  둘 다 저장할 때 정화되는 'rich' 칸만 받는다
- **토큰** — 세션·재설정·신청조회·올린 파일 이름이 모두 `randomBytes`/`randomUUID` 다
  (`Math.random` 을 쓰는 곳이 없다). 재설정은 3시간·한 번 쓰면 죽음·새로 받으면 앞 것
  무효·바꾸면 열린 로그인 모두 끊음까지 갖췄다
- **방문 기록**은 브라우저가 JS 를 돌려야만 세므로 크롤러가 숫자에 섞이지 않고,
  물음표 뒷부분을 떼어 담아 주소 종류가 한없이 늘지 않는다

### 알아 둘 것 (고치지 않음)
- 방문 기록만 앱 쪽 횟수 제한이 없다. Nginx 가 주소당 초당 50건으로 막고 90일이 지나면
  지우므로 그대로 둔다. 디스크가 빠르게 차는 일이 보이면 여기를 먼저 본다

## 2026-09-22 (관리자 화면 점검 · 명단 내려받기)

관리자 화면 18개를 **빈 DB 상태로 실제로 열어 본 적이 없어서**, 새로 만든 DB 에
관리자 한 명만 넣고 전부 열어 보았다. 권한도 로그인 안 한 사람 · 일반 회원
두 경우로 눌러 보았다.

### 고친 것
- **교육사업 제안 CSV 의 신청일이 하루 빨랐다.** 화면 목록은 `formatDate` 로 한국
  날짜를 보여 주는데 내려받기만 DB 시각(UTC)을 그대로 잘라 썼다. 한국 시각 오전
  9시 전에 들어온 신청이 전날로 적힌다. 같은 줄의 접수번호(`EP-260922-…`)는 한국
  날짜로 매기므로 한 줄 안에서 날짜가 어긋났다. `toKst` 를 거치게 했다

        DB(UTC) 2026-09-21 23:30  =  한국 2026-09-22 08:30
          고치기 전  신청일 2026-09-21   ← 접수번호는 260922
          고친 뒤    신청일 2026-09-22   ← 화면과 같다

- **내려받기 셋이 같은 코드를 저마다 들고 있었다.** `src/lib/csv.ts` 를 만들어 두고도
  제안 목록만 쓰고 뉴스레터·사업공고는 옛 코드를 그대로 갖고 있었다. 위의 날짜가
  한 곳만 어긋난 까닭이다. 셋 다 한곳을 쓰게 했다. 덤으로 명단이 비었을 때
  머리글 뒤에 붙던 빈 줄이 사라졌다
- **`toCsv` 의 빈 값 처리가 헛돌고 있었다.** 부르는 쪽에서 `String(cell)` 을 먼저
  씌워 넘겨, 빈 값을 빈 칸으로 바꾸려던 `?? ""` 가 닿지 못했다. 빈 값이 `null`
  이라는 글자로 칸에 박힌다. 지금 내보내는 칸은 모두 NOT NULL 이라 드러나지
  않았을 뿐이다(SQLite·PostgreSQL 양쪽 확인). 나중에 빈 값이 되는 칸이 하나
  늘면 바로 새므로 근원에서 막았다
- 검사 `tests/csv.test.ts` 를 새로 썼다(남은 일에 적어 둔 것). BOM · 빈 명단 ·
  따옴표와 줄바꿈이 섞인 값 · 빈 값 · 숫자. 검사에서 부르려고 `csv.ts` 안의
  `@/lib/format` 을 `./format.ts` 로 바꿨다. node 검사 실행기는 `@/` 를 모른다

### 확인했고 문제 없던 것
- **빈 DB 에서 관리자 화면 18개가 모두 정상**(대시보드·접속기록·계정보안·회원사·
  파일·메인화면·메일기록·회원·뉴스레터·사업공고·소개·연혁·팝업·게시글·제안·
  사이트정보·통계·휴지통). 숫자가 0 인 화면도 빈 표로 잘 그려진다
- **권한** — 로그인 안 한 사람과 일반 회원 모두 화면 18개는 로그인으로 돌려보내고,
  명단 내려받기 셋은 403 이다. 관리자 아닌 사람에게 내용이 비치는 곳은 없다
- CSV 셋 다 맨 앞에 BOM(EF BB BF)이 있다. 엑셀에서 한글이 깨지지 않는다
- **소셜 로그인은 설정이 없으면 단추가 아예 나오지 않는다.** 주소로 직접 들어가도
  `/login?social=unavailable` 로 돌려보내고 500 이 나지 않는다. 임시 주소로 열 때
  서비스에 돌아올 주소를 등록하지 않아도 화면이 깨지지 않는다는 뜻이다
- 첨부파일 내려받기는 잠금글이면 403, 휴지통에 든 글의 첨부는 주소를 알아도 404

### 알아 둘 것 (고치지 않음)
- 이미 로그인한 사람이 `/login` 을 열면 로그인 폼이 **1초쯤 보였다가** 첫 화면으로
  넘어간다. Next 가 흘려보내는 중에 `redirect()` 를 만나면 307 대신 meta refresh
  를 끼워 넣기 때문이다(`next/dist/docs/.../redirect.md`). 일반 회원이 `/admin` 에
  들어왔을 때도 같은 길을 지나므로, 까닭을 모른 채 첫 화면으로 밀려난다.
  드문 길이고 고치려면 관리자 문지기 코드를 건드려야 해서 그대로 둔다

## 2026-09-22 (메일 문안 확인)

지금까지 메일이 '나가는가'만 봤지 '무엇이 적혀 나가는가'는 본 적이 없어서,
문안 11가지를 실제로 찍어 보았다(접수·승인·반려·제안 접수/완료·사무국 알림·
가입 승인·가입 신청 알림·비밀번호 재설정).

### 고친 것
꼬리말 구분선 앞의 빈 줄이 메일마다 달랐다. 접수 메일만 한 줄 띄고 나머지 넷은
마지막 문장에 구분선이 붙어 나갔다. 부르는 쪽이 저마다 줄바꿈을 붙이게 해 둔 탓에
한 곳만 붙고 나머지가 빠졌다. **꼬리말이 제 여백을 갖도록** 옮겼다.
이제 11가지가 모두 같은 간격이다. HTML 로 감쌀 때 꼬리말이 갈라지는 것도 확인했다.

### 확인했고 문제 없던 것
- 문안 11가지에 빈칸·`undefined`·깨진 문장 없음. 반려 사유가 없을 때도 '사유' 칸이
  통째로 빠져 자연스럽다
- 접수번호·조회 주소·문의 주소가 모두 `SITE_URL` 을 따라 바뀐다
- 두 번 들어가는 문제 — 회원·뉴스레터·사업공고에 유일 제약이 있고, 공개 폼 네 개는

## 2026-09-22 (회원 전용 글이 새던 것)

### 고친 것
회원 전용(잠금) 글의 **본문이 로그인하지 않은 사람에게 두 갈래로 새고 있었다.**

1. **머리말(meta)** — 글 상세의 설명을 본문에서 뽑아 쓰고 있었다. 그래서 잠근 글도

2. **통합검색** — 본문으로 찾고 본문으로 미리보기를 만드는데 잠금 여부를 보지 않았다.

   로그인하지 않았으면 본문으로 찾지도, 미리보기를 보여 주지도 않게 했다.
   **제목으로는 그대로 찾힌다** — 제목은 목록에 이미 보이는 것이라 막을 이유가 없다.

확인: 본문에만 있는 낱말을 심은 잠금글을 만들어 두 쪽에서 비교했다.

    누가            본문검색  머리말에 본문  화면에 본문
    로그인 안 함     안 뜸     없음          안 보임
    로그인함        뜸        없음          보임

머리말은 로그인 여부와 상관없이 게시판 설명을 쓴다. 머리말은 검색엔진이 가져가는
것이라 보는 사람에 따라 달라지면 안 되기 때문이다.
