# C3R 홈페이지 리뉴얼 (Front)

한국클라우드컴퓨팅연구조합(C3R) 홈페이지 프론트엔드. Next.js 16 (App Router) + Tailwind CSS v4 + TypeScript.

```bash
npm run dev
```

http://localhost:3000

## 게시판 · 로그인 (데이터베이스)

게시판과 로그인은 SQLite 파일 하나로 동작합니다. 별도 DB 서버를 설치할 필요가 없고,
드라이버도 Node 내장 `node:sqlite` 라서 네이티브 빌드가 없습니다. **Node 22 이상**이 필요합니다.

첫 실행 전에 관리자 계정을 만듭니다. 스키마는 이때 자동으로 생성됩니다.

```bash
node scripts/create-admin.mjs admin@cccr.or.kr "비밀번호" "최고관리자"
```

**로컬 개발은 SQLite, 운영 서버는 PostgreSQL**을 씁니다. 같은 코드가 두 방언 모두에서 동작하며,
어느 쪽을 쓸지는 `DB_DRIVER` 하나로 정합니다.

| 환경변수 | 기본값 | 설명 |
| --- | --- | --- |
| `DB_DRIVER` | `sqlite` | `sqlite` 또는 `postgres` |
| `DATABASE_PATH` | `data/c3r.db` | (sqlite) 파일 경로 |
| `DATABASE_URL` | — | (postgres) `postgres://user:pw@host:5432/c3r` |
| `DATABASE_SSL` | — | `1`이면 TLS로 접속 |
| `UPLOAD_DIR` | `data/uploads` | 첨부파일 저장 폴더 |

`data/`는 `.gitignore`에 있습니다. **OneDrive·Dropbox 같은 동기화 폴더 안에 두면 파일 잠금 때문에
쓰기가 실패할 수 있으므로**, 운영 서버에서는 동기화 밖 경로를 `DATABASE_PATH`로 지정하세요.

- 스키마는 `src/lib/db/migrations/<방언>/*.sql`을 이름순으로 한 번씩 적용합니다. 바꿀 때는 기존 파일을 고치지 말고 `002_*.sql`을 추가하세요.
- 비밀번호는 `node:crypto`의 scrypt로 해시하며(`scrypt$salt$hash`), 세션은 DB에 해시만 저장하고 쿠키에는 원문 토큰을 httpOnly로 내려보냅니다.
- 첨부파일은 `public/`이 아니라 `data/uploads`에 두고 `/api/attachments/[id]`에서 권한을 확인한 뒤 내보냅니다. 회원 전용 글의 첨부는 비로그인 시 403입니다.
- 헤더가 로그인 상태를 표시하므로 루트 레이아웃에서 쿠키를 읽습니다. 그래서 모든 페이지가 요청 시 렌더링(SSR)됩니다.

### 메인 화면 관리 (`/admin`)

메인의 **히어로 슬라이드 · 배너 띠 · 알림판**은 코드가 아니라 DB(`home_cards`)에 있고,
관리자로 로그인하면 헤더의 "메인 화면 관리"에서 직접 고칩니다.

- 카드마다 추가 · 수정 · 순서 이동(↑↓) · 숨기기 · 삭제가 됩니다. 숨기기는 목록에 남고 화면에서만 빠집니다.
- 종류마다 쓰는 칸이 다릅니다. 슬라이드는 분류·제목(줄바꿈 가능)·본문·캡션·날짜·링크,
  배너는 분류 배지·제목·부제·링크, 알림판은 태그·제목·설명·링크입니다.
- 링크는 `/`로 시작하는 사이트 안 주소이거나 `http(s)://` 주소만 받습니다. 바깥 주소는 새 창으로 열립니다.
- 슬라이드를 모두 지우면 히어로가 비고, 배너를 모두 지우면 배너 띠 자체가 사라집니다.

지금 들어 있는 문구는 화면 구성을 위해 만든 자리표시자입니다. 실제 내용으로 바꿔 주세요.

### 게시판 추가하기

게시판 화면은 `src/components/board/`의 공용 컴포넌트(`BoardListView`, `PostDetailView`,
`PostWriteView`, `PostEditView`)를 함께 씁니다. 게시판마다 목록·상세·글쓰기·수정 화면이
복사되지 않습니다.

현재 게시판은 여섯입니다.

| 게시판 | 주소 | 목록 | 비고 |
| --- | --- | --- | --- |
| 공지사항 | `/board/notice` | 표 | |
| 행사정보 | `/board/events` | 카드 | 주최·장소·일시, 상태 자동 계산 |
| 산업뉴스 | `/info/news` | 표 | |
| 기술동향 | `/info/trends` | 표 | |
| 자료실 | `/info/archive` | 표 | 첨부·회원 전용 잠금 활용 |
| 뉴스레터 | `/info/newsletter` | 표 | 목록 위에 구독 신청 배너 |

주소는 사이트 메뉴 구조를 따르므로 두 갈래(`/board/[board]`, `/info/[board]`)의 라우트가
있고, 어느 쪽이든 같은 공용 컴포넌트를 부릅니다. 같은 글이 두 주소에서 열리지 않도록
각 라우트는 `getBoardAt()`으로 **주소가 일치하는 게시판만** 통과시키고 나머지는 404입니다
(예: `/board/news`는 404).

새 게시판은 두 곳만 손대면 됩니다.

1. `src/lib/boards.ts`의 `BOARDS`에 한 줄 추가 — `slug`, 이름, 설명, `basePath`,
   목록 표시 방식(`table`/`cards`), 행사 전용 입력 여부, 메인 노출 여부(`showOnHome`).
2. 마이그레이션으로 `boards` 테이블에 같은 `slug` 행 추가 (두 방언 모두).

`basePath`가 `/board/…`나 `/info/…`이면 라우트 파일은 만들지 않아도 됩니다.
다른 메뉴에 두려면 그 경로에 얇은 라우트 4개(목록·상세·글쓰기·수정)를 추가하고
공용 컴포넌트를 부르면 됩니다.

메인 새소식은 `showOnHome: true`인 게시판만 모읍니다. 여섯 개를 모두 걸면 탭이
한 줄을 넘겨 읽기 어려워서, 공지사항·행사정보·산업뉴스만 노출합니다.

행사정보(`events`)는 `hasEventFields: true`라 주최·장소·행사 시작일/종료일·신청 마감일을 함께 받습니다.
목록의 **접수중·예정·종료 표시는 저장하지 않고 날짜에서 계산**합니다(`eventStatus`, `src/lib/format.ts`).
관리자가 상태를 손으로 바꾸지 않아도 지난 행사가 접수중으로 남지 않습니다.

### 본문 편집기

글 본문은 Tiptap 편집기로 작성하고 **HTML 문자열**로 저장합니다.

| 묶음 | 도구 |
| --- | --- |
| 실행 | 되돌리기, 다시 실행 |
| 글자 | 글자체 14종(맑은 고딕·돋움·굴림·바탕·궁서·나눔·본고딕/명조·Arial 등), 크기 16단계(10~72), 글자색 32색, 배경색 24색 — 둘 다 색상표에서 직접 고르기 가능, 굵게·기울임·밑줄·취소선, 글자 코드, 서식 지우기 |
| 문단 | 큰·중간·작은 제목, 줄간격, 글머리표·번호 목록, 인용, 코드 블록, 좌·중·우·양쪽 정렬 |
| 넣기 | 링크(해제 포함), 이미지, 표(행·열 추가/삭제·셀 합치기), 구분선 |
| 원본 | HTML 직접 편집 |

- **HTML 모드**: `HTML` 버튼을 누르면 원본을 직접 고칠 수 있고, 다시 누르면 편집 화면에
  반영됩니다. 다른 곳에서 만든 HTML을 붙여 넣을 때 씁니다.
- 이미지는 툴바 버튼 외에 **붙여넣기·끌어다 놓기로도** 올라갑니다.

### 게시글 링크 칸

본문 안의 하이퍼링크와 별개로, 글마다 **링크 한 줄**(주소 + 표시할 이름)을 붙일 수 있습니다.
기사 원문이나 신청 페이지처럼 "이 글이 가리키는 곳"을 상세 화면 위쪽 단추로 보여줍니다.
`http://`·`https://`로 시작하는 주소만 저장합니다(`posts.link_url`, `posts.link_label`).

- **저장 전에 서버에서 한 번 더 거릅니다** (`src/lib/html.ts`). 관리자만 글을 쓰지만 서버 액션은
  화면을 거치지 않고도 호출할 수 있어, 허용 태그·속성·style 값만 남기고 스크립트와 이벤트
  핸들러는 제거합니다. 이미지는 `/api/images/{id}` 형태(우리 서버에 올린 것)만 남습니다.
- 편집 화면과 실제 글 화면이 `globals.css`의 `rich-text` 유틸리티를 함께 써서 보이는 대로 저장됩니다.
- 본문 이미지는 `images` 테이블 + `data/uploads`에 저장하고 `/api/images/[id]`가 인라인으로
  내보냅니다(첨부파일과 달리 내려받기가 아니라 화면에 그려져야 하므로). 글을 지우면 다른 글이
  쓰지 않는 이미지도 함께 지웁니다.
- 편집기 도입 전에 쓴 글은 태그가 없으므로 상세 화면이 줄바꿈만 살려 그대로 보여줍니다.

### 두 방언을 함께 유지하는 규칙

`src/lib/db/drivers/`의 SQLite·PostgreSQL 구현이 같은 `Driver` 인터페이스(`src/lib/db/driver.ts`)를 따릅니다.
쿼리를 새로 쓸 때 아래만 지키면 두 방언에서 똑같이 동작합니다.

- 자리표시자는 `?`만 씁니다. PostgreSQL 드라이버가 `$1, $2 …`로 바꿉니다. (SQL 문자열 리터럴 안에는 `?`를 쓰지 않습니다.)
- `datetime('now')` 같은 방언 함수 대신 `now()`(`src/lib/db/driver.ts`)로 앱에서 시각을 넣습니다.
- 새 행의 id는 `RETURNING id`로 받습니다.
- 참/거짓은 0/1 정수 컬럼으로 두고 `= 1`로 비교합니다.
- 스키마를 바꾸면 `migrations/sqlite/`와 `migrations/postgres/` **양쪽에** 같은 번호의 파일을 추가합니다.

토큰은 `src/app/globals.css`의 `@theme` 블록에 정의되어 있습니다. Tailwind 클래스에서 `bg-navy-900`, `text-brand-600` 처럼 바로 씁니다.

| 역할 | 토큰 | 값 |
| --- | --- | --- |
| 히어로·푸터 배경 | `navy-900` | `#062A55` |
| 주요 액션·링크 | `brand-600` | `#1257A5` |
| 액센트 (활성 탭, NEW, TOP) | `flame-500` | `#F05A28` |
| 섹션 배경 | `surface` | `#F5F8FC` |
| 본문 텍스트 | `ink-900` | `#14202E` |
| 구분선 | `line` | `#E2E8F0` |

### 타이포그래피

임의 크기(`text-[0.9rem]`)를 쓰지 말고 아래 스케일만 사용합니다. `@theme`의 `--text-*` 토큰으로 정의되어 있습니다.

| 클래스 | 크기 | 용도 |
| --- | --- | --- |
| `text-2xs` | 11px | 날짜·용량 등 데이터 라벨 |
| `text-xs` | 12px | 캡션 |
| `text-sm` | 13px | 보조 텍스트 |
| `text-base` | 14px | 버튼·폼 등 UI 기본 |
| `text-md` | 15px | 본문 |
| `text-lg` | 17px | 카드 제목 |
| `text-xl` | 20px | 소제목 |
| `text-2xl` | 24px | 섹션 제목 |
| `text-3xl` | 32px | 서브페이지 제목 |
| `text-4xl` | 44px | 메인 히어로 |

- **본문/제목**: Pretendard Variable (CDN). 국문 제목은 `letter-spacing: -0.03em` 적용.
- **`label-mono`**: IBM Plex Mono. 날짜·용량·Vol 번호 등 **라틴 숫자 데이터 전용**.
- **`data-line`**: 한글이 섞인 데이터 줄(건수·기간·등급). mono는 한글 글리프가 없어 자간이 어긋나므로 본문 서체를 씁니다.

### 장식에 대한 원칙

- **번호(01/02/03)는 실제 순서일 때만** 씁니다. 가입 절차·회원가입 단계처럼 순서가 정보를 담는 곳만 해당하며, 병렬 항목에는 쓰지 않습니다.
- **eyebrow는 장식이 아니라 데이터**입니다. 제목을 영어로 반복하지 말고 건수·기간·분류 같은 실제 값을 넣습니다. 가능하면 배열 길이에서 계산해 데이터와 어긋나지 않게 합니다.
- **`hex-field`(육각 패턴)는 메인 히어로에서만** 씁니다. 반복되면 텍스처가 벽지가 되어 히어로가 특별해 보이지 않습니다. 서브페이지 헤더는 하단 액센트 라인 한 줄로 대신합니다.

```
        ├── posts.ts       # 게시글 조회 (목록·상세·이전다음)
        └── post-actions.ts# 글 등록·수정·삭제 서버 액션
```

서브페이지를 추가할 때는 `PageShell`에 `href`만 넘기면 `site-data.ts`의 `NAV`에서 대메뉴·형제 탭·breadcrumb을 자동으로 구성합니다.

## 남은 작업

- **실제 콘텐츠 교체 필요.** `page-data.ts`와 `site-data.ts`의 게시물·회원사·연혁·교육과정은 화면 구성을 위해 작성한 예시입니다.
- **반영 완료된 실제 정보**: 이사장(이동기), 설립연도(2009), 조직 구성(총회·이사회·이사장·감사·자문위원회·사무국 + 4개 팀), 부서별 연락처와 이메일(`cccr.or.kr`), 인사말 전문, 조합 표어, 사무실 2곳(삼성 사무실 / 구로 교육장)의 주소·전화·팩스·교통편.
- **아직 자리표시자**: 고유번호(`000-00-00000`), 행사정보·교육과정·정보서비스(산업뉴스·기술동향·자료실·뉴스레터) 목록.
- **연혁**: 2008년 창립총회부터 2023년까지 전 기간 실제 자료가 반영되어 있습니다(15개 연도, 249건). 연도를 추가하려면 `page-data.ts`의 `HISTORY` 배열에 넣으면 탭이 자동으로 늘어납니다.
- **원문 오타 그대로 옮긴 곳**: 구로 교육장 시내버스 안내의 "디지털산업1단지 정류장 하처"(→ 하차로 보임). `page-data.ts`의 `OFFICES`에서 수정할 수 있습니다.
- **인사말 본문의 "지난 10년간"**: 조합 공식 문구를 그대로 옮겼으나 2009년 설립 기준으로 작성 시점이 2019년경으로 보입니다. 현재 기준으로 갱신이 필요한지 확인이 필요합니다.
- **개인정보처리방침·이메일무단수집거부는 조합이 제공한 실제 문안**입니다(`src/lib/legal-data.ts`). 푸터에서 누르면 원본 사이트처럼 두 갈래 탭 팝업으로 열리고, `/privacy`·`/email-policy` 페이지도 같은 데이터를 씁니다.
- **법무 검토 필요**: 이용약관은 아직 표준 문안이므로 시행 전 검토가 필요합니다.
- **이미지**: 회원사 로고, 유관기관 로고, 이사장 사진은 자리표시자입니다. (전달 예정) 확보 후 `next/image`로 교체하세요.
- **지도**: 찾아오시는 길의 지도는 격자 배경 자리표시자입니다. 카카오/네이버 지도 API 연동이 필요합니다.
- **게시판 6개(공지사항·행사정보·산업뉴스·기술동향·자료실·뉴스레터)가 DB로 동작합니다**: 목록·검색·페이지네이션·상세·이전다음글·조회수, 관리자 글쓰기/수정/삭제, 첨부파일 업로드·다운로드, 회원 전용 글 잠금. 기존 사이트의 과거 게시물은 이관하지 않았습니다.
- **아직 UI만 있는 기능**: 회원가입, 아이디 찾기·비밀번호 재설정, 뉴스레터 구독 신청(폼만 있고 접수 처리 없음).
- **메인 화면 문구는 관리자 화면에서 바꿉니다**(`/admin`). 지금 값은 자리표시자입니다.
- **교육은 조합이 별도 사이트로 운영합니다**(`EDUCATION_URL`, `site-data.ts`). 사이트 안에 교육 페이지를 두지 않고, 헤더의 "교육 홈페이지"·빠른링크 "교육 신청"·알림판·배너의 교육 항목이 모두 새 창으로 그 사이트를 엽니다. 바깥 주소는 `SmartLink`가 자동으로 새 창 처리합니다.
- **영문 페이지**: `/en`은 안내 페이지만 있습니다. 전체 번역은 별도 작업입니다.
